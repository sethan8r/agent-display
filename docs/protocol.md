# Протокол хаб ↔ плата

Это общий язык хаба (Python, на компе) и прошивки (плата). Меняешь что-то здесь — меняешь обе стороны.

## Коротко, по-простому

- Хаб раз в секунду шлёт плате **одну строку JSON** — полный снимок: все сессии, лимиты, время.
  Плата ничего не помнит между снимками (кроме лимитов в NVS) — просто перерисовывает экран.
- Если что-то поменялось (агент начал ждать подтверждения), хаб шлёт снимок сразу, не дожидаясь секунды.
- **Хаб думает, плата рисует.** Хаб обрезает длинный текст, выкидывает символы, которых нет в шрифте,
  выбирает статус и иконку. Плата только раскладывает готовое по экрану и считает «4 мин» из времени.
  Так большинство правок попадает в хаб, а он обновляется вместе с плагином — без перепрошивки.
- Плата в ответ почти молчит: при старте и после потери связи говорит `hello` со своей версией прошивки.
  По ней плагин понимает, что пора обновить прошивку.

## Канал

| | |
|---|---|
| Порт | USB Serial (CH340), 8N1 |
| Скорость | **921600** бод — проверено на плате: 0 ошибок на снимках по 23 КБ |
| Кадр | одна строка UTF-8 JSON, в конце `\n`. Внутри строки переводов строк нет |
| Макс. длина строки | 32 КБ. Плата заводит буфер приёма под это (`Serial.setRxBufferSize`) |

- Хаб открывает порт с `dtr=False`, `rts=False` — иначе открытие порта перезагружает плату.
- **Мусор игнорируется обеими сторонами.** При включении ESP32 сам печатает служебный текст загрузчика,
  при подключении могут прийти обрывки строк. Строка не разобралась как JSON или нет поля `t` → молча
  пропустить.
- Неизвестные поля игнорируются. Отсутствующее необязательное поле = значение по умолчанию (см. таблицы).

## Хаб → плата: `snap` (снимок)

Шлётся раз в 1 сек, плюс сразу при изменении (но не чаще 5 раз в сек).

```json
{
  "t": "snap",
  "v": 1,
  "now": 1761400000,
  "tz": 10800,
  "limits": {
    "5h": { "pct": 42, "reset": 1761410000 },
    "7d": { "pct": 87, "reset": 1761800000 }
  },
  "sessions": [
    {
      "id": "80d59de8",
      "name": "agent-display",
      "status": "wait",
      "wait_for": "perm",
      "since": 1761399760,
      "icon": "ask",
      "action": "Bash: npm run build",
      "ctx": 42,
      "tokens": 84000,
      "tokens_max": 200000,
      "model": "Opus 5.5",
      "dir": "VSCodeProjects/agent-display",
      "started": 1761396000,
      "subagents": [
        { "type": "Explore", "task": "Найти конфиг роутера" }
      ],
      "subagents_more": 0
    }
  ],
  "sessions_more": 0,
  "fw_update": "0.2.0"
}
```

### Верхний уровень

| Поле | Тип | Обяз. | Что это |
|---|---|---|---|
| `t` | `"snap"` | да | тип сообщения |
| `v` | int | да | версия протокола (см. «Версии»). Плата читает его **первым** |
| `now` | int | да | текущее время, Unix-секунды UTC. У платы нет часов — всё время берётся отсюда |
| `tz` | int | да | смещение часового пояса в секундах (Москва = 10800). Чтобы показать «сброс в 18:00» |
| `limits` | object | нет | лимиты подписки. Нет поля — хаб их не знает (нет обёртки статус-строки, не Pro/Max, ещё не было ответа API) → плата показывает сохранённые в NVS |
| `sessions` | array | да | сессии **в порядке показа** (по времени запуска). Пусто — агентов нет |
| `sessions_more` | int | нет (0) | сколько сессий не влезло в снимок (лимит — 20) |
| `fw_update` | string | нет | в плагине лежит прошивка новее, чем на плате — показать значок «есть обновление» |

### `limits.5h` / `limits.7d`

Каждое окно может отсутствовать отдельно.

| Поле | Тип | Что это |
|---|---|---|
| `pct` | int 0–100 | сколько израсходовано, % |
| `reset` | int | когда сбросится, Unix-секунды UTC |

Если `now ≥ reset` — плата пишет «сброшен», а не старые проценты. То же правило для значений из NVS.

### Сессия

| Поле | Тип | Обяз. | Что это |
|---|---|---|---|
| `id` | string | да | короткий стабильный id (8 символов). Плата по нему держит открытым экран подробностей, даже если порядок поменялся |
| `name` | string ≤ 40 | да | `session_name` или имя папки проекта |
| `status` | enum | да | см. ниже |
| `wait_for` | enum | нет | только при `status: "wait"` — чего именно ждёт: `perm` / `question` / `plan` (см. ниже) |
| `since` | int | да | с какого момента идёт текущее: старт задачи (`work`, `subs`, `wait`) или конец (`done`, `error`), Unix-сек. Плата сама пишет «работает 4 мин» / «готов 12 мин назад» |
| `icon` | enum | нет | иконка перед `action`. Неизвестная → без иконки |
| `action` | string ≤ 80 | нет | что делает / о чём спрашивает, уже сжато хабом. На главном экране — 1 строка с «…», в подробностях — до 2 строк |
| `ctx` | int 0–100 | нет | % контекста. Нет — полоска пустая/серая (бывает в начале сессии и после `/compact`) |
| `tokens`, `tokens_max` | int | нет | для «84k / 200k» в подробностях |
| `model` | string ≤ 24 | нет | `model.display_name` |
| `dir` | string ≤ 40 | да | папка проекта, последние 1–2 уровня |
| `started` | int | да | когда открыта сессия (возраст — только в подробностях) |
| `subagents` | array ≤ 4 | нет ([]) | живые субагенты: `type` (≤ 20) и `task` (≤ 40) |
| `subagents_more` | int | нет (0) | сколько ещё субагентов сверх 4 («+N ещё») |
| `summary` | string ≤ 80 | нет | только `done`: что сделал — первая строка последнего ответа Claude (`last_assistant_message` из `Stop`) |
| `quiet` | int | нет | только `work`: сколько секунд не было ни одного события хуков. От 120 плата пишет «тишина N мин» — думает над чем-то тяжёлым или завис |

**`status`** — цвет рамки и подпись:

| Значение | Когда | Источник (для хаба) |
|---|---|---|
| `idle` | сессия открыта, задач ещё не было | `SessionStart` |
| `work` | работает | `UserPromptSubmit`, `PreToolUse` |
| `subs` | сам закончил, но ждёт своих субагентов | `Stop` с непустыми `background_tasks` |
| `wait` | **ждёт тебя**: подтверждение или вопрос (мигает) | `PermissionRequest`, `Notification` `permission_prompt` |
| `done` | закончил | `Stop` без фоновых задач |
| `error` | упал с ошибкой API | `StopFailure` |

**`wait_for`** — чего ждёт сессия в статусе `wait` (рамка мигает во всех трёх случаях, отличается подпись):

| Значение | Что | Источник (для хаба) |
|---|---|---|
| `perm` | просит разрешение на действие (`action`: «Bash: npm run build») | `PermissionRequest` по любому инструменту, кроме двух ниже |
| `question` | задал тебе вопрос с вариантами (`action`: текст вопроса) | `PreToolUse` с `tool_name: "AskUserQuestion"` |
| `plan` | показал план и ждёт одобрения | `PreToolUse` с `tool_name: "ExitPlanMode"` |

Нет поля или неизвестное значение → плата показывает просто «ждёт тебя».
Источники `question` и `plan` проверить на живом хабе (в тестовом режиме `-p` эти окна не появляются).

**`icon`**: `edit` (Edit/Write), `run` (Bash/PowerShell), `read` (Read), `find` (Grep/Glob),
`web` (WebFetch/WebSearch), `agent` (вызов субагента), `ask` (ждёт подтверждения), `other`.

### Текст

- **Хаб не шлёт текст интерфейса.** Подписи статусов («Работает» / «Working»), время («4 мин» / «4 min»),
  шутливые фразы — всё на плате, на языке из её настроек (RU / EN). Хаб шлёт только данные и то, что
  написал сам пользователь или Claude: названия, команды, вопросы, задачи субагентов.
- UTF-8. Хаб заранее выкидывает всё, чего нет в шрифте платы (эмодзи и т.п.), и переводы строк.
- Длины выше — в символах, не байтах. Хаб обрезает с `…`. Плата всё равно не должна падать на длинной
  строке — обрезает по ширине экрана.

## Плата → хаб: `hello`

Шлётся при старте платы и на первый снимок после потери связи (тишина > 6 сек).
Так хаб узнаёт версию, даже если плата включилась раньше, чем он открыл порт.

```json
{"t": "hello", "fw": "0.1.0", "proto": 1, "board": "cyd2usb"}
```

| Поле | Что это |
|---|---|
| `fw` | версия прошивки (semver). Хаб сравнивает с `firmware.bin` в плагине → `fw_update` |
| `proto` | версия протокола, которую понимает прошивка |
| `board` | ревизия платы (на будущее, если появятся другие) |

## Плата → хаб: `log` (для отладки)

```json
{"t": "log", "msg": "touch calibrated"}
```

Хаб пишет это в свой лог-файл. Так можно отлаживать плату, не отнимая у хаба порт.

## Версии

`v` — целое число, меняется **только** при несовместимых правках: переименовали поле, поменяли смысл
или единицы. Добавили необязательное поле — `v` не трогаем (старая прошивка его просто не увидит).
Так прошивку приходится обновлять реже.

Плата сравнивает `v` со своей версией протокола:

| | Экран |
|---|---|
| совпало | обычная работа |
| `v` больше | «Плагин новее прошивки. Обнови прошивку: `/agent-display:update-firmware`» |
| `v` меньше | «Прошивка новее плагина. Обнови плагин: `/plugin update agent-display`» |

## Связь пропала

Нет ни одного валидного `snap` 6 сек → плата показывает «хаб не подключён»: лимиты серые с пометкой
«давно не обновлялось», список агентов скрыт (он мог устареть).

## Объём

| Ситуация | Размер строки | Передача + разбор (замер на плате) |
|---|---|---|
| нет агентов | ~150 Б | — |
| 5 агентов | ~2 КБ | ~60 мс |
| 20 агентов, все поля до упора кириллицей, по 4 субагента | ~23 КБ (потолок) | ~0.7 сек, разбор JSON 14 мс |

Замер тестовой прошивкой на 921600: 50 снимков по 23 КБ, ошибок 0, реальная скорость 33 КБ/с.
Узкое место — чтение порта по одному байту; в основной прошивке читать кусками (`Serial.read(buf, n)`).

## Примеры

Агентов нет, хаб на связи (плата показывает шутливую фразу):

```json
{"t":"snap","v":1,"now":1761400000,"tz":10800,"limits":{"5h":{"pct":3,"reset":1761410000}},"sessions":[]}
```

Только что открытая сессия, лимиты ещё неизвестны:

```json
{"t":"snap","v":1,"now":1761400000,"tz":10800,"sessions":[{"id":"9b2e45cd","name":"agent-display","status":"idle","since":1761399990,"dir":"VSCodeProjects/agent-display","started":1761399990}]}
```

Работает, контекст после `/compact` неизвестен:

```json
{"t":"snap","v":1,"now":1761400000,"tz":10800,"sessions":[{"id":"9b2e45cd","name":"Рефакторинг хаба","status":"work","since":1761399760,"icon":"edit","action":"Edit hub/serial.py","model":"Opus 5.5","dir":"agent-display/plugin","started":1761396000}]}
```
