# agent-display

Маленький сенсорный дисплей (ESP32 CYD), который одним взглядом показывает статусы всех запущенных
сессий Claude Code на компьютере: кто работает, кто закончил, кто ждёт подтверждения, кто ждёт субагентов.
Сценарий: одновременно работает много агентов, и видно, что с каждым, на отдельном экране, без переключения окон.

Всё ниже — принятые решения и проверенные факты. Отброшенные идеи собраны в отдельном разделе —
не предлагать их заново без новой причины.

**Состояние: версия 1.0.0, работает целиком.** Установка по README проверена с нуля 2026-10-25: плагин с GitHub
на чистой установке + новая плата с заводской прошивкой, прошитая командой `/agent-display:update-firmware`.
Порядок установки и сам процесс прошивки не трогать без причины — они работают.

## Железо

- ESP32-2432S028 «Cheap Yellow Display», версия с двумя портами (micro-USB + USB-C, «CYD2USB»).
  Дисплей ST7789-совместимый (ID 04h = `81 81 D9`, не ILI9341), матрица TN, без инверсии, RGB, rotation 0 = USB снизу.
  Тач XPT2046. ESP32-D0WD-V3 rev 3.1, flash 4 МБ, PSRAM нет. RGB-светодиод на обороте.
- **Только micro-USB**: по USB-C Windows плату не видит. USB-UART CH340, драйвер Windows ставит сама. 921600 бод — без ошибок.
- **Датчик света (LDR) бесполезен** — всегда 0 → авто-яркости нет, только ползунок.
- Ориентация вертикальная, USB вниз → экран 240 × 320.
- Тач резистивный (стилус/ноготь): кнопки ≥ ~35 px, тап по агенту — на всю строку, листание кнопками ▲▼, не свайпом.
  Калибровка при первом запуске (стрелки в 4 углах — `calibrateTouch` из LovyanGFX; макет рисует так же), хранится
  в NVS, в настройках — «перекалибровать».
- У платы нет часов: время присылает хаб в каждом сообщении. NVS писать только при изменениях (износ flash).
- Корпус (печатаю сам, `enclosure/`): нужен доступ к RST и BOOT, светодиод внутри не виден без световода,
  TN блёкнет под углом → экран чуть наклонить к себе. Размеры снимать с живой платы.

## Архитектура

```
сессия 1 ─┐
сессия 2 ─┼─ хуки плагина ─→ хаб (Python, фон) ─ USB Serial, JSON Lines ─→ плата
сессия 3 ─┘                  помнит всех, раз в ~1 сек шлёт полный снимок
```

Почему хаб: плагин — не живая программа, а скрипты, которые Claude Code дёргает по событиям; ждущий подтверждения
агент событий не шлёт; COM-порт держит только одна программа, а открытие порта может перезагрузить плату; для общей
картины и лимитов нужен кто-то один.

- **Плагин** (`plugin/`): хуки, хаб, обёртка статус-строки, команды `/agent-display:setup` и
  `/agent-display:update-firmware`, готовая прошивка, вендоренные pyserial / esptool / intelhex (без pip).
  Ставится с GitHub: `/plugin marketplace add sethan8r/agent-display` → `/plugin install agent-display@agent-display`.
- **Хуки**: `type: "http"` на `http://127.0.0.1:47800/hook` (не `localhost` — лишний заход через IPv6), таймаут 1 сек.
  `SessionStart` — command-хук (`py -3 … || python3 … || python …`, async): http там не поддерживается; он же
  запускает хаб и обновляет копию обёртки статус-строки. Плагин **никогда** не тормозит и не ломает Claude Code.
- **Хаб** (`scripts/hub.py`) — единственный владелец COM-порта. Отвечает мгновенно (`{}`), работа — под коротким
  локом. Гаснет через 5 мин без сессий. Лог и обёртка — в `~/.claude/agent-display/` (**не** в
  `${CLAUDE_PLUGIN_DATA}`: её удаляют вместе с плагином, и статус-строка пропала бы).
  Безопасность: только локальные запросы без `Origin` (браузерные страницы отсекаются; CORS `null` — для макета с
  диска), PID проверяется на тип, цикл не падает от одной ошибки.
- **Плата ↔ хаб**: при открытии порта хаб шлёт `{"t":"ping"}`, плата отвечает `hello` (`fw`, `proto`, `board`).
  Нет `hello` за 5 сек — чужое устройство (CH340 бывает и у принтера), порт отпускается на минуту.
  Нет данных от хаба 5–6 сек — плата показывает «хаб не подключён».
- **Жизнь сессии**: агент на экране, пока сессия открыта. `/exit`, Ctrl+C → `SessionEnd` → пропадает сразу.
  Окно закрыли без события → хаб раз в секунду проверяет процесс сессии → пропадает через 2–3 сек.
  PID: для http-хука — владелец клиентского сокета (это `claude.exe` сессии); для command-скриптов — ближайший
  предок `claude.exe`. Хранится PID + время создания процесса (PID переиспользуются). По имени процесса искать
  нельзя: десктопное приложение Claude тоже `claude.exe`.
- **Версия формата** `"v": N` в каждом снимке. Не совпала → плата пишет понятное сообщение, а не кашу.
- **Прошивка и обновление** — `/agent-display:update-firmware` (`scripts/update_firmware.py`, `commands/update-firmware.md`).
  Хаб сравнивает `fw` из `hello` с `plugin/firmware/firmware.json` → шлёт плате `fw_update`. Команда спрашивает
  подтверждение, хаб по `POST /release` отпускает порт, esptool пишет **только приложение** (NVS цел: калибровка,
  яркость, раскладка), хаб забирает порт обратно. Плата без `hello` (новая / чужая прошивка) или аргумент `full` →
  ещё загрузчик и таблица разделов. Окирпичить нельзя: загрузчик цел, можно повторить. Ошибки Claude читает в той же
  сессии и помогает.
- **Релиз**: поднять `FW_VERSION` в `firmware/src/app/model.h` и `version` в `plugin/.claude-plugin/plugin.json`,
  затем `py -3 firmware/tools/publish.py` (собирает env `main`, кладёт `.bin` + `firmware.json` в `plugin/firmware/`),
  коммит, push. Версия плагина **фиксирует** установку: без нового номера `claude plugin update` ничего не скачает.
  Авто-обновление для сторонних marketplace по умолчанию выключено — обновляются командами из README.
- Ручная прошивка через `pio run -e main -t upload` не пройдёт, пока хаб держит порт — хаб сначала погасить.

## Откуда данные (сверено с докой и живыми тестами)

| Что | Откуда |
|---|---|
| % контекста, токены (84k / 200k) | статус-строка: `context_window.used_percentage`, `context_window_size`, `total_input_tokens`; запасной путь — usage последнего ответа из `transcript_path` |
| Лимиты 5ч / 7д + сброс | статус-строка: `rate_limits.five_hour` / `seven_day` (`used_percentage`, `resets_at` в epoch-секундах) |
| Название | статус-строка: `session_name` (`/rename` или AI-заголовок); нет → имя папки проекта |
| Модель | статус-строка: `model.display_name` |
| Папка проекта | `cwd` во всех хуках |
| Что делает | `PreToolUse`: `tool_name` + `tool_input` |
| Ждёт подтверждения (и о чём) | `PermissionRequest` (и от субагентов) / `Notification` (matcher `permission_prompt`); снимается `PostToolUse` или `PostToolUseFailure` |
| Закончил | `Stop` (`StopFailure` — ошибка API) |
| Начал задачу (старт таймера) | `UserPromptSubmit`; промт `<task-notification>…` — это завершение фонового субагента, не новая задача |
| Субагенты | `SubagentStart` / `SubagentStop` (`agent_id`, `agent_type`); описание — `tool_input.description` вызова `Agent` в `PreToolUse`; `Stop` / `SubagentStop` несут `background_tasks` (id → описание). `Stop` при живых `background_tasks` = «ждёт субагентов» |
| Конец сессии | `SessionEnd` + проверка процесса |
| Отказ в разрешении / Esc | **хуков нет** (`PermissionDenied` — только в авто-режиме) → хаб смотрит конец transcript: `[Request interrupted by user…]` → «без задачи» |

**Статус-строка**: плагин не может задать её сам (в настройках плагина работают только `agent` и
`subagentStatusLine`). `/agent-display:setup` (один раз, со спросом) ставит обёртку: она выводит прежнюю статус-строку
пользователя без изменений и пересылает JSON хабу. `/agent-display:setup remove` возвращает как было. Без обёртки
пропадают только лимиты. `settings.json`: читать с `utf-8-sig`; не парсится → ничего не трогать; писать атомарно;
`.bak` один раз. Команда обёртки — `py -3 "…/statusline.py"`: работает и в Git Bash, и в PowerShell.

Справка по докам: общие поля хуков — `session_id`, `transcript_path`, `cwd`, `permission_mode`, `hook_event_name`
(+ `agent_id`, `agent_type` у субагентов). Статус-строка обновляется по событиям (дебаунс 300 мс) и может молчать в
простое; `rate_limits` — только Pro/Max и после первого ответа API, окна могут отсутствовать; `used_percentage`
бывает `null` в начале сессии и после `/compact`. `${CLAUDE_PLUGIN_ROOT}` меняется при обновлении — состояние там не
хранить. HTTP-хук при выключенном хабе не тормозит (отказ мгновенный), но пишется как `hook_non_blocking_error`.

## Экраны

**Шрифт** Inter, кириллица (не транслит). **Заранее отрисованные bitmap-шрифты LVGL** (4 bpp, во flash, 0 байт RAM):
`py -3 firmware/tools/gen_fonts.py` качает TTF в `firmware/fonts/` и рисует Pillow в `firmware/src/app/fonts/*.c` —
Inter 10–16 px обычный и полужирный, полужирный 24 px (фраза пустого экрана), значки 12 / 16 / 30 / 56 px. Набор:
латиница + Latin-1, кириллица (русская с Ё, украинская), – — … № стрелки. Символы вне шрифта (эмодзи) хаб выкидывает.
**Значки** — Font Awesome Free Solid 6.5.2, **16 px всегда**, независимо от размера текста; 12 px — только в
маленьких «таблетках» (шапка, ▲▼) и у лимитов. Значок — отдельная подпись своим шрифтом, выровненная по заглавным
буквам строки (`icon_at` / `icon_in_row`). НЕ смешивать значки с текстом через fallback шрифта: у Inter свои глифы
на тех же кодах → мусор.
**Скорость отрисовки**: bitmap-шрифты, без `clip_corner`, SPI 80 МГц, один буфер LVGL на 64 строки (выровнен
`alignas(LV_DRAW_BUF_ALIGN)` — невыровненный LVGL молча отвергает → чёрный экран) → кадр ~40 мс, мигание всех карточек
синхронно. Время меньше минуты — «<1 мин»: тикающие секунды перестраивали бы экран каждую секунду.
**Размер текста** — настройка 13 / 14 / 16 px (по умолчанию 14). Это размер названий; остальной текст 11 / 12 / 13.

**Названия**: `session_name` → иначе имя папки. НЕ заставлять Claude придумывать название промтом. Одна строка;
длинное — **бегущая строка** (3 сек стоит, едет ~25 px/с, 1 сек стоит, прыгает в начало). Прочие длинные строки — «…».

**Главный экран** — у каждого агента:
- название; время текущей задачи («работает 4 мин») или «готов 12 мин назад»;
- что делает (`✎ Edit auth.ts`) или о чём спрашивает (`⚠ Bash: npm run build`), в 1 строку;
- цвет рамки и фон 15 % по статусу: работает / готов / ждёт тебя (мигает) / ждёт субагентов / ошибка / без задачи;
- полоска % контекста;
- **третья строка — только на тексте 16 в раскладке «Крупно»** (карточка всегда выше, 3 агента на страницу вместо 4):
  ждёт тебя → вопрос/команда целиком в 2 строки; готов → что сделал (`summary`); работает и ≥2 мин без событий →
  «тишина N мин» (`quiet`); ждёт субагентов → задача первого; иначе папка · модель.
- Порядок по времени запуска, новый в конце; строки не прыгают (ждущих наверх НЕ поднимаем).
- Не влезают → кнопки ▲▼; ждущий за экраном — мигающий ⚠ на кнопке в его сторону (только значок, текст не влезает).
- Внизу всегда лимиты 5ч и неделя.
- **Раскладка** (в настройках, у каждой платы своя): «Крупно» (~4 агента), «Компактно» (~7–8 строк), «Сетка 2×N».
  Базовый вид — список на всю ширину (~30 символов в названии), не сетка (в 120 px ~15 символов).
  Элементы растягиваются по высоте до ▲▼ — по числу мест на странице, а не агентов (последняя страница такая же).

**Подробности** (тап по агенту): полное название; контекст полоской и «84k / 200k»; что делает / о чём спрашивает
(1–2 строки); субагенты по строке (`Explore · Найти конфиг роутера`, максимум 4, дальше «+N ещё»); папка, модель;
время; лимиты. Назад — кнопкой или сам через 30 сек.

**Настройки** (шестерёнка): тема тёмная / светлая, язык RU / EN, размер текста, яркость, раскладка, перекалибровка.
Светлая тема — насыщенные цвета и непрозрачные рамки (TN на белом гасит бледное). Весь текст интерфейса живёт на
плате, хаб шлёт только данные → язык — настройка платы. Всё в NVS. Подсветку сама плата не гасит и не убавляет.

**Пустые состояния**:
- хаб на связи, агентов нет → по центру крупно: кружка 56 px, шутливая фраза 24 px, «нет агентов» 14 px.
  Фраз по 16 на язык (список — в `design/index.html` и `firmware/src/app/i18n.h`); новая случайная при каждом
  появлении пустого экрана и раз в 2 мин, не та же, что в прошлый раз;
- хаб не подключён (комп выключен / плагин не работает) → отдельное сообщение;
- лимиты хранятся в NVS (`pct` + `resets_at`, каждое окно отдельно); новое окно пишется сразу, изменившийся процент —
  не чаще раза в 10 мин. Хаб на связи и `resets_at` прошёл → «сброшен»; хаба нет → серые + «давно не обновлялось»;
  данных не было никогда → пусто.

## Отброшенные идеи (и почему)

- Каждая сессия сама шлёт JSON раз в 2–3 сек → ждущий агент молчит и пропал бы; порт держит один процесс. Заменено хабом.
- Wi-Fi → лишняя настройка пароля и поиск платы, а плата и так на USB у своего компа.
- Веб-прошивальщик (ESP Web Tools) → прошивка и обновление — одной командой плагина.
- Звук; авто-притушение подсветки; метка «не просмотрено»; последние 5 действий в подробностях → не нужны.
- Тап по агенту выводит окно на компе вперёд → в IDE работает только для окна, не вкладки; тап открывает подробности.
- Свободный конструктор раскладки → 3 пресета. Раскладка «Подробно» (третья строка всегда, 3 агента) → третья строка
  только на тексте 16.
- Транслит → кириллический шрифт. TinyTTF (рендер TTF на плате) → падал по памяти при листании; `npx lv_font_conv`
  заблокирован фильтром безопасности → свой конвертер на Pillow.
- Значки Lucide / Phosphor → Font Awesome Solid (выбрано на плате).
- Сортировка «ждущие наверх» → стабильный порядок + значок на ▲▼.
- Сетка как основной вид → не влезает в 240 px; основной — список.
- Два репо (код и плагин) → монорепо: прошивка и плагин говорят на одном формате.
- TFT_eSPI → LovyanGFX (экран и тач одной библиотекой, ревизия задаётся в коде).

## Технологии

PlatformIO (espressif32 7.1.3) + Arduino + LVGL 9.6 + LovyanGFX 1.2.31 + ArduinoJson 7.4.3, версии зафиксированы в
`platformio.ini`. Envs: `main` (рабочая), `demo` (витрина с симуляцией), `hwtest` (проверка железа). Своя таблица
разделов `partitions.csv` (одно приложение на 4 МБ). Хаб, хуки, обёртка — Python, только stdlib + вендоренные пакеты.
Тесты хаба: `py -3 -m unittest discover plugin/tests`. Проверка плагина: `claude plugin validate .` и
