# agent-display

Маленький сенсорный дисплей (ESP32 CYD), который одним взглядом показывает статусы всех запущенных
сессий Claude Code на компе: кто работает, кто закончил, кто ждёт подтверждения, кто ждёт субагентов.
Основной сценарий: одновременно работает много агентов, и я хочу видеть, что с каждым, на отдельном
маленьком экране, а не прыгать по окнам на компе.

Этот файл — итог долгого обсуждения (планировочная сессия 2026-10-25, id `40789110-40df-4e6c-93c0-02a0d0617ee2`,
запускалась из `C:\Users\Maksim`). Всё ниже — уже принятые решения. Отброшенные идеи собраны в отдельном
разделе — не предлагай их заново без новой причины.

## Железо

- Плата: ESP32-2432S028 «Cheap Yellow Display», версия с двумя портами (micro-USB + USB-C, «CYD2USB»).
  **Проверено тестовой прошивкой (2026-10-25)**: дисплей ST7789-совместимый (ID 04h = `81 81 D9`,
  D3h = `00 00 00`, т.е. не ILI9341), матрица TN; **без инверсии, RGB, rotation 0 = USB снизу** — всё по
  умолчанию. Тач XPT2046 калибруется и попадает. Чип ESP32-D0WD-V3 rev 3.1, flash 4 МБ, PSRAM нет.
  RGB-светодиод на обороте.
- **Датчик света (LDR) на этой плате бесполезен**: всегда 0, хоть закрой, хоть свети фонариком →
  авто-яркости нет, только ползунок.
- USB-UART CH340, драйвер встал сам, у меня **COM5**. **Работать через micro-USB**: по USB-C Windows
  плату вообще не увидела (кабель рабочий — проверено). 921600 бод — 0 ошибок на снимках по 23 КБ.
- Ориентация: **вертикально, USB смотрит вниз** → экран 240 (ширина) × 320 (высота).
- Плат две: моя и кореша, прошивка одинаковая, каждая на своём компе.
- Плата будет в корпусе, который я напечатаю на 3D-принтере (поставить можно куда угодно).
  Для корпуса нужны: доступ к RST и BOOT (хотя бы иголкой), RGB-светодиод внутри корпуса не виден без
  световода; TN-матрица блёкнет под углом → экран лучше чуть наклонить к себе. Координаты снять с живой платы.
- Тач резистивный: работает нажатием (у меня есть стилус и ногти). Кнопки ≥ ~35 px, тап по агенту —
  на всю строку/ячейку, листание кнопками ▲▼, а не свайпом. Калибровка при первом запуске (4 крестика
  по углам), хранится в NVS, в настройках — «перекалибровать».
- **У платы нет часов**: текущее время присылает хаб в каждом сообщении.
- NVS писать только при изменениях (износ flash).

## Архитектура (решено)

```
сессия 1 ─┐
сессия 2 ─┼─ хуки плагина ─→ хаб (Python, фон) ─ USB Serial, JSON Lines ─→ плата
сессия 3 ─┘                  помнит всех, раз в ~1 сек шлёт полный снимок
```

**Почему так, а не «каждая сессия сама шлёт JSON»**: плагин Claude Code — это не живущая программа, а
набор скриптов, которые Claude Code дёргает по событиям. Агент, который ждёт подтверждения, событий
не генерирует. COM-порт может держать только одна программа (как телефонная трубка), а открытие
порта может перезагрузить плату. И для общей картины + лимитов нужен кто-то один, кто помнит всех.

- **Плагин** Claude Code: хуки + хаб + обёртка статус-строки + команда обновления прошивки + готовый
  `firmware.bin`. Ставится из публичного GitHub-репо `sethan8r/agent-display`:
  `/plugin marketplace add sethan8r/agent-display` → `/plugin install agent-display@agent-display`.
  Обновления приходят оттуда же.
- **Хаб** — единственный владелец COM-порта. Запускается сам из хука первой сессии (если ещё не запущен),
  сам гаснет через несколько минут без сессий. Для меня и кореша невидим.
- **Хуки** шлют события хабу. Предпочтительно `type: "http"` на localhost с коротким таймаутом (~1 сек) —
  без запуска процесса на каждое событие. Альтернатива — command-хук с `async: true`.
  Плагин **никогда** не должен тормозить или ломать Claude Code.
- **Связь** USB Serial, JSON Lines (одна строка = полный снимок). Пара КБ/сек — с огромным запасом.
- **Жизнь сессии**: агент на экране, пока сессия открыта (неважно — работает, закончил, ждёт).
  Ушла нормально (`/exit`, Ctrl+C) → `SessionEnd` → пропадает сразу. Окно просто закрыли → события нет,
  поэтому хаб раз в секунду проверяет, жив ли процесс Claude этой сессии → пропадает через 2–3 сек.
  PID берём из самого HTTP-запроса хука: хаб смотрит, какой процесс владеет клиентским сокетом
  (проверено — это `claude.exe` сессии). Хранить PID + время создания процесса (PID бывает переиспользован).
  По имени процесса искать нельзя: десктопное приложение Claude тоже `claude.exe`. Monitor не нужен.
- Плата: если от хаба нет данных 5–6 сек — состояние «хаб не подключён».
- **Python**: плагин сам ищет рабочий интерпретатор (`py -3`, потом `python`), иначе хаб тихо не
  запустится. pyserial (и esptool для обновления) положить в плагин — чистый Python, без pip.
- **Версия формата**: `"v": N` в каждом сообщении. Не совпала → плата пишет понятное сообщение
  («Плагин новее прошивки, нужна перепрошивка»), а не кашу. Важно, т.к. прошивку кореша обновляю я.
- **Обновление прошивки**: команда плагина `/agent-display:update-firmware`. Плата сама скажет, когда
  пора (по версии). Хаб отпускает порт → esptool пишет **только приложение** (не стирает NVS:
  калибровка тача, яркость, раскладка сохраняются) → хаб подхватывает порт. Перед прошивкой спрашивает,
  сама молча не обновляется. Окирпичить почти нельзя: загрузчик цел, можно повторить. Если ошибка —
  Claude в той же сессии видит вывод и помогает (кореш может обновлять «вместе с Claude»).
- `firmware.bin` пока храню прямо в репо (~1 МБ на версию — ок). Позже можно GitHub Actions.

## Откуда данные (проверено по докам)

| Что | Откуда |
|---|---|
| % контекста, токены (84k / 200k) | статус-строка: `context_window.used_percentage`, `context_window_size`, `total_input_tokens`; запасной путь — usage последнего ответа из `transcript_path` |
| Лимиты 5ч / 7д + время сброса | статус-строка: `rate_limits.five_hour` / `seven_day` (`used_percentage`, `resets_at` в epoch-секундах) |
| Название | статус-строка: `session_name` (`/rename` или AI-заголовок); нет → имя папки проекта |
| Модель | статус-строка: `model.display_name` |
| Папка проекта | `cwd` во всех хуках |
| Что делает | `PreToolUse`: `tool_name` + `tool_input` |
| Ждёт подтверждения (и о чём) | `PermissionRequest` / `Notification` (matcher `permission_prompt`) |
| Закончил | `Stop` (`StopFailure` — ошибка API) |
| Начал задачу (старт таймера) | `UserPromptSubmit` |
| Субагенты | `SubagentStart` / `SubagentStop` (`agent_id`, `agent_type`); описание задачи (3–5 слов) — `tool_input.description` вызова субагента; инструменты субагента приходят с `agent_id` |
| Конец сессии | `SessionEnd` + проверка процесса |

**Статус-строка**: плагин не может сам её задать (в настройках плагина работают только `agent` и
`subagentStatusLine`). Поэтому команда настройки плагина (запускается один раз, спрашивает) встраивает
нашу обёртку: она пересылает JSON хабу и запускает прежнюю статус-строку пользователя, выводя её результат.
Чужую статус-строку не ломать. Без обёртки пропадают только лимиты (контекст достаём из transcript).

## Экраны

**Шрифт** Inter (как в макете), кириллица — не транслит. Лежит в прошивке как TTF (`firmware/fonts/`),
рисует LVGL TinyTTF — любой размер без генерации. `npx lv_font_conv` заблокирован фильтром безопасности,
поэтому не bitmap. **Кэш глифов TinyTTF держать маленьким** (16 на шрифт): с умолчанием 128 десять
шрифтов съели кучу и плата падала. Символы вне шрифта (эмодзи и т.п.) хаб молча выкидывает.
**Размер текста — настройка 13 / 14 / 16 px, по умолчанию 14** (на плате читается всё от 10, но издалека
нужно 14–16). Это размер названий; остальной текст 11 / 12 / 13, карточки подрастают вместе с ним.

**Названия**: `session_name` → иначе имя папки проекта. НЕ заставлять Claude придумывать название промтом.
Всегда в одну строку; длинное — **бегущая строка**: 3 сек стоит в начале, едет до конца (~25 px/с),
1 сек стоит, прыгает в начало. Прочие длинные строки — обрезка «…».

**Главный экран** — агенты, у каждого:
- название;
- время текущей задачи («работает 4 мин») или «готов 12 мин назад» (возраст сессии — только в подробностях);
- что делает сейчас (`✎ Edit auth.ts`); если ждёт подтверждения — о чём спрашивает, сжато в 1 строку
  (`⚠ Bash: npm run build`), длинное обрезается «…»;
- цвет рамки по статусу: работает / закончил / ждёт подтверждения (мигает, видно издалека) / ждёт субагентов;
- полоска % контекста.
- Порядок **по времени запуска**: новый в конце, закрытый пропадает, остальные съезжают. Строки не прыгают
  (ждущих наверх НЕ поднимаем).
- Не влезают → кнопки ▲▼; если ждущий подтверждения за экраном — значок на кнопке («⚠ 2 ниже»).
- Внизу всегда лимиты 5ч и неделя.
- **Раскладка** — пресет в настройках (у каждой платы свой, хранится в NVS):
  «Крупно» (~4 агента списком), «Компактно» (~7–8 строк), «Сетка 2×N» (короткие названия).
  Для вертикального экрана базовый вид — список строк на всю ширину (~30 символов в названии),
  а не сетка (в 120 px влезает ~15 символов).

**Подробности** (тап по агенту):
- полное название;
- контекст полоской + цифрами «84k / 200k»;
- что делает / о чём спрашивает — сжато, 1–2 строки;
- субагенты — по одной строке на каждого (`Explore · Найти конфиг роутера`), максимум 4, дальше «+N ещё»;
- папка проекта, модель;
- время;
- лимиты внизу, как на главном.
- Назад — кнопкой или автоматически через 30 сек.

**Настройки** (маленькая кнопка-шестерёнка): тема «Тёмная / Светлая», язык интерфейса RU / EN,
размер текста 13 / 14 / 16, яркость ползунком, раскладка, перекалибровка тача.
Светлая тема — насыщенные цвета и непрозрачные рамки (на белом TN гасит бледное; подобрано на плате).
Фон карточки — 15 % цвета статуса (выбрано из 0/6/10/15), ждущая — сильнее и мигает. Весь текст интерфейса живёт на
плате (хаб шлёт только данные), поэтому язык — чисто настройка платы. Всё в NVS, переживает перезагрузку. Подсветку НЕ гасить и не убавлять сама по себе.

**Пустые состояния**:
- хаб на связи, агентов нет → по центру шутливая фраза (16 штук на язык, например
  «Не пора ли нам повайбкодить?», «Хватит смотреть рилсы, когда есть свободные токены»; список — в `design/index.html`): случайная при каждом появлении пустого экрана, не та же, что в прошлый раз;
- хаб не подключён (комп выключен / плагин не работает) → отдельное сообщение;
- лимиты: последние хранятся в NVS вместе со временем получения и `resets_at`.
  Хаб на связи и `resets_at` прошёл → «сброшен» (а не устаревшие 87%);
  хаба нет → серые + «давно не обновлялось»; данных никогда не было (свежая плата) → пусто.

## Отброшенные идеи (и почему)

- Каждый агент сам шлёт JSON раз в 2–3 сек, без данных 5–6 сек — пропадает → ждущий агент молчит
  и пропал бы; порт держит один процесс. Заменено хабом.
- Wi-Fi → лишняя настройка пароля и поиск платы, а плата и так на USB у своего компа.
- Веб-прошивальщик (ESP Web Tools) для кореша → обе платы прошиваю я; обновления — командой плагина.
- Звук / пищалка → не нужен.
- Авто-притушение подсветки → электричество не экономим, яркость только из настроек.
- Метка «не просмотрено» → экран для обзора, не для отметок.
- Последние 5 действий в подробностях → не нужно.
- Тап по агенту выводит окно на компе вперёд → в IDE не работает точно (только окно, не вкладка); вместо
  этого тап открывает подробности.
- Свободный конструктор раскладки → 2–3 пресета.
- Транслит → кириллический шрифт.
- Сортировка «ждущие наверх» → стабильный порядок + значок на ▲▼.
- Сетка 2×3 как основной вид → не влезает в 240 px ширины, основной — список.
- Два репо (код и плагин) → один монорепо: прошивка и плагин говорят на одном формате.
- Отдельный модуль автообновления → это одна команда внутри плагина.
- TFT_eSPI → LovyanGFX (экран и тач одной библиотекой, ревизия задаётся в коде, без правки файлов библиотеки).

PlatformIO + Arduino + LVGL 9 + LovyanGFX + ArduinoJson. Версии библиотек зафиксировать в `platformio.ini`.
Хаб и хуки — Python (pyserial вендорить в плагин).

описание — только для каталога Anthropic, нам не нужны. Имя плагина не может начинаться с `claude-`.

## Справка по докам Claude Code (на 2026-10-25)

- Общие поля хуков: `session_id`, `transcript_path`, `cwd`, `permission_mode`, `effort`, `hook_event_name`;
  у субагентов ещё `agent_id`, `agent_type`.
- Типы хуков: `command`, `http` (POST на URL), `prompt`, `agent`, `mcp_tool`. `async: true` — command-хук
  в фоне, не блокирует. Таймауты по умолчанию: command/http 600 сек (30 на `UserPromptSubmit`) — свой
  ставить маленьким.
- Статус-строка обновляется по событиям с дебаунсом 300 мс + `refreshInterval` (сек, мин 1); в простое
  может молчать. `rate_limits` есть только у Pro/Max и только после первого ответа API; каждое окно может
  отсутствовать; после `resets_at` окно пропадает. `used_percentage` контекста может быть `null` в начале
  сессии и после `/compact`. `session_name` отсутствует, если нет ни `/rename`, ни AI-заголовка.
- Плагин: hooks, skills, commands, agents, MCP-серверы, LSP, `experimental.monitors` (команда, которую
  Claude Code держит фоновым процессом с начала сессии — возможный способ «жива ли сессия»; проверить,
  что вывод монитора не засоряет чат). Переменные: `${CLAUDE_PLUGIN_ROOT}` (меняется при обновлении —
  не хранить там состояние), `${CLAUDE_PLUGIN_DATA}` (постоянная папка данных плагина).
- `PermissionRequest` может вернуть решение — основа для «разрешить с платы» (на потом).

## Проверить первым делом (до основного кода)

Проверено 2026-10-25 на Claude Code 2.1.310 (`claude -p --settings <tmp>.json`, хуки только на тестовый запуск):

- [x] HTTP-хук, когда хаб выключен: **не тормозит** (отказ соединения мгновенный), но **ругается** —
  каждое событие пишется как `hook_non_blocking_error`, а в `-p` печатается `SessionEnd hook ... failed`.
  Хаб завис → Claude ждёт ровно `timeout` хука и идёт дальше. Выводы: хаб стартует command-хуком на
  `SessionStart` (http там не поддерживается) и не гаснет, пока жив хоть один PID сессии; хаб отвечает
  мгновенно (событие в очередь, ответ `{}`); таймаут http-хуков 1 сек; URL только `127.0.0.1`, не
  `localhost` (иначе лишний заход через IPv6).
- [x] Процесс сессии: PID из сокета HTTP-хука (см. «Жизнь сессии»). Command-хуки на этом компе
  запускаются через `bash.exe` (Git Bash), родитель цепочки — тот же `claude.exe`.
- [x] Субагенты: `PreToolUse` с `tool_name: "Agent"` даёт `tool_input.description` (+ `subagent_type`,
  `tool_use_id`); `SubagentStart/Stop` дают `agent_id` + `agent_type`; `Stop` и `SubagentStop` несут
  `background_tasks: [{id = agent_id, description, agent_type, status}]` — готовая связка id → описание.
  Инструменты субагента приходят с его `agent_id`. `Stop` при живых `background_tasks` = «ждёт субагентов»,
  а не «закончил». Завершение фонового субагента приходит как `UserPromptSubmit` с промтом
  `<task-notification>…` — это не новая задача, таймер не сбрасывать.
- [ ] Как выглядят ошибки хуков в обычном (интерактивном) окне при выключенном хабе — посмотреть глазами.
- [x] Точная ревизия платы и драйвер дисплея — см. «Железо». Тестовая прошивка: `firmware/`, env `hwtest`
  (экраны листаются тапом или командами по USB: `next`, `screen N`, `inv`, `bgr`, `rot N`, `theme`, `info`, `ldr`).
- [ ] Плагин из подпапки `plugin/` ставится через marketplace (проверить у меня, с разрешения).
