# agent-display

Маленький сенсорный дисплей (ESP32 CYD), который одним взглядом показывает статусы всех запущенных
сессий Claude Code на компе: кто работает, кто закончил, кто ждёт подтверждения, кто ждёт субагентов.

## Как со мной работать

- Общаемся на русском, объясняй простым языком: я новичок в микроконтроллерах.
- Мои идеи — не жёсткое ТЗ. Если есть способ лучше — говори прямо и объясняй почему.
- **Спрашивай перед**: прошивкой платы, установкой плагина в мой Claude Code, изменением моей
  статус-строки, публикацией на GitHub (push, создание репо).
- Коммиты на английском: `type(scope): message`, например `feat(hub): add serial reconnect`.
- Порядок работы: функционал (решён, см. ниже) → формат JSON → дизайн в HTML (утверждаю я) → код и прошивка.
- Всё сверяй с официальной документацией Claude Code (code.claude.com/docs), не по памяти.

## Железо

- Плата: ESP32-2432S028 «Cheap Yellow Display», версия с двумя портами (micro-USB + USB-C, «CYD2USB»).
  У этой версии обычно дисплей **ST7789 с инвертированными цветами** (а не ILI9341) — проверить
  тестовой прошивкой. Тач резистивный XPT2046, датчик света (LDR), RGB-светодиод на обороте.
- USB-UART CH340, у меня на COM5. **Работать через micro-USB**: USB-C с кабелем C–C не определяется.
- Ориентация: **вертикально, USB смотрит вниз** (экран 240×320).
- Плат две: моя и кореша. Обе прошиваю я. Плата будет в напечатанном корпусе (нужны окно под LDR
  и доступ к RST/BOOT — координаты снять с платы).

## Архитектура (решено)

```
сессии Claude Code ─ хуки плагина ─→ хаб (Python, фон) ─ USB Serial, JSON Lines ─→ плата
```

- **Плагин** Claude Code: хуки + хаб + обёртка статус-строки + команда обновления прошивки + готовый
  `firmware.bin`. Ставится из этого GitHub-репо:
  `/plugin marketplace add sethan8r/agent-display` → `/plugin install agent-display@agent-display`.
- **Хаб** — единственный владелец COM-порта (порт может держать одна программа; открытие порта может
  перезагрузить плату). Помнит все сессии, раз в ~1 сек шлёт плате полный снимок одной строкой JSON.
  Запускается сам из хука первой сессии, сам гаснет через несколько минут без сессий.
  Для меня и кореша он невидим: поставил плагин, воткнул плату — работает.
- **Хуки** шлют события хабу. Предпочтительно `type: "http"` на localhost с коротким таймаутом
  (без запуска процесса на каждое событие). Плагин **никогда** не должен тормозить или ломать Claude Code.
- **Жизнь сессии**: сессия на экране, пока открыта. Ушла по `SessionEnd`, либо (окно просто закрыли)
  хаб раз в секунду проверяет, жив ли процесс Claude этой сессии → пропадает через 2–3 сек.
  Агент, который ждёт подтверждения или закончил, НЕ пропадает, пока сессия открыта.
- Плата: если от хаба нет данных 5–6 сек — состояние «хаб не подключён».
- **Python на Windows**: команда `python` может быть заглушкой Microsoft Store (у меня так).
  Плагин сам ищет рабочий Python: `py -3`, потом `python`. pyserial — положить в плагин (чистый Python),
  без pip.
- **Версия формата** (`"v": N`) в каждом сообщении. Не совпала → плата пишет «нужна перепрошивка».
- **Обновление прошивки**: команда плагина `/agent-display:update-firmware` — хаб отпускает порт,
  esptool пишет только приложение (не стирает NVS: калибровка тача и настройки сохраняются),
  хаб подхватывает порт. Перед прошивкой спрашивает.

## Откуда данные (проверено по докам)

| Что | Откуда |
|---|---|
| % контекста, токены (84k / 200k) | статус-строка: `context_window.used_percentage`, `context_window_size`; запасной путь — usage из transcript |
| Лимиты 5ч / 7д + время сброса | статус-строка: `rate_limits.five_hour` / `seven_day` (`used_percentage`, `resets_at`) |
| Название | статус-строка: `session_name` (`/rename` или AI-заголовок); иначе имя папки проекта |
| Модель | статус-строка: `model.display_name` |
| Что делает | хук `PreToolUse`: `tool_name` + `tool_input` |
| Ждёт подтверждения (и о чём) | хук `PermissionRequest` / `Notification` (permission_prompt) |
| Закончил | хук `Stop` |
| Субагенты | `SubagentStart` / `SubagentStop` (`agent_id`, `agent_type`); описание задачи — из `tool_input` вызова субагента |
| Конец сессии | `SessionEnd` + проверка процесса |

**Статус-строка**: плагин не может сам её задать (в настройках плагина разрешены только `agent` и
`subagentStatusLine`). Поэтому команда настройки встраивает нашу обёртку: она пересылает JSON хабу и
запускает прежнюю статус-строку пользователя (у меня — cc-usage-monitor), выводя её результат.
Чужую статус-строку не ломать. Без обёртки пропадают только лимиты.

## Экраны

Шрифт LVGL с кириллицей: латиница + кириллица (с Ё) + цифры + пунктуация + — « » … № ° ✓ стрелки +
иконки LVGL. Символы вне набора хаб выкидывает. Размер выбрать на живой плате (тестовый экран
10/12/14/16 px), ориентир 14 px названия / 12 px остальное.

**Главный** — список агентов, у каждого:
- название; время текущей задачи («работает 4 мин») или «готов 12 мин назад»;
- что делает сейчас; если ждёт подтверждения — о чём спрашивает, сжато в 1 строку (`⚠ Bash: npm run build`);
- цвет рамки по статусу: работает / закончил / ждёт подтверждения (мигает, видно издалека) / ждёт субагентов;
- вертикальная полоска % контекста.
- Порядок: по времени запуска, новый в конце, закрытый пропадает — остальные съезжают (строки не прыгают).
- Не влезают → кнопки ▲▼; если ждущий подтверждения за экраном — значок на кнопке («⚠ 2 ниже»).
- Внизу всегда лимиты 5ч и неделя.
- Раскладка — пресет в настройках: «Крупно» (~4), «Компактно» (~7–8 строк), «Сетка 2×N».

**Подробности** (тап по агенту): полное название, контекст полоской + «84k / 200k», что делает / о чём
спрашивает (1–2 строки), субагенты — по строке на каждого (`Explore · Найти конфиг роутера`, максимум 4,
дальше «+N ещё»), папка проекта, модель, лимиты внизу. Назад — кнопкой или само через 30 сек.

**Настройки** (маленькая кнопка-шестерёнка): яркость «Авто / Вручную» + ползунок (авто по LDR —
грубо, 2–3 уровня), раскладка, перекалибровка тача. Всё хранится в NVS. Подсветку не гасить.

**Пустые состояния**:
- хаб есть, агентов нет — по центру шутливая фраза из ротации («Не пора ли нам повайбкодить?» и т.п.);
- хаб не подключён — отдельное сообщение;
- лимиты: последние хранятся в NVS с временем получения; у платы нет часов (время шлёт хаб).
  Прошёл `resets_at` → «сброшен», хаба нет → серые + «давно не обновлялось», данных нет → пусто.

## Технологии

PlatformIO + Arduino + LVGL 9 + LovyanGFX (экран и тач одной библиотекой, ревизия задаётся в коде)
+ ArduinoJson. Версии библиотек зафиксировать в `platformio.ini`.

## Структура репо

```
.claude-plugin/marketplace.json  витрина для /plugin marketplace add
plugin/                          плагин: хуки, хаб, статус-строка, update-firmware, firmware.bin
firmware/                        исходники прошивки (PlatformIO)
design/                          HTML-макеты экранов 240×320
docs/protocol.md                 формат JSON хаб → плата (общий язык)
```

## Проверить первым делом (до основного кода)

- [ ] HTTP-хук, когда хаб выключен: Claude Code не тормозит и не ругается.
- [ ] На Windows надёжно находится процесс Claude Code сессии (для проверки «жива ли»).
- [ ] Описание задачи субагента достаётся из хука.
- [ ] Точная ревизия платы и драйвер дисплея (тестовая прошивка — спросить перед прошивкой).
- [ ] Плагин из подпапки `plugin/` ставится через marketplace.
